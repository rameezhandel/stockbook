# Play Store listing assets

## Privacy policy

Play requires a policy URL from every app, including one that collects nothing.

**Published at:** <https://sites.google.com/view/stockbook-privacy/home> — confirmed reachable signed out, which is the check that matters.

Hosted on Google Sites rather than from this repository: GitHub Pages needs a
public repo, and this one is private. The **source of truth is still
[`../docs/privacy/index.html`](../docs/privacy/index.html)** — edit that, then
copy the wording across, so the policy stays version-controlled alongside the
code whose behaviour it describes.

Two things that silently break this URL:

- **Never paste a link containing `?authuser=`.** That is a parameter from a
  signed-in Google session, not part of the public address.
- **Google Sites defaults sharing to your organisation.** The page then looks
  right to you and shows a sign-in wall to everyone else, which fails review.
  Check it in a private window while signed out.

## Listing artwork

Generated by [`../tools/make_play_assets.py`](../tools/make_play_assets.py) —
rerun it rather than editing these by hand, so the launcher icon and the listing
icon stay the same drawing.

| File | Where it goes | Google's rules |
| --- | --- | --- |
| `icon-512.png` | Store listing → App icon | 512×512, 32-bit PNG, **no transparency**, no rounded corners — Play masks it itself. |
| `feature-graphic.png` | Store listing → Feature graphic | 1024×500, no transparency. Shown at the top of the listing and in Play's own promo slots. |

Both are opaque and drawn from the same mark as the app's launcher icon, which
is the iOS icon redrawn for Android's adaptive shapes: an adaptive icon is 108dp
of which only the centre 66dp survives every launcher mask, so the book is drawn
smaller here than on iOS, where nothing is cropped.

## Screenshots are not here, and cannot be generated

Play requires **at least 2** phone screenshots, and they must be of the app
actually running. These have to be captured on a real phone — nothing in this
repository can produce them, and a mock-up of a screen would be both a rejection
risk and a lie about what the app looks like.

Install the APK, set the shop up with believable data — not "test test 123" —
and capture:

1. **Home** with a month's sales showing and something pending to collect.
2. **Sales** mid-bill: a couple of lines, a customer chosen, the total visible.
3. **A customer's statement**, which is the screen that best explains what the
   app is for.
4. **Items**, showing the shelf with stock counts.
5. **A bill with a photograph of the paper attached** — the thing no other
   ledger app in this category does.

Google's constraints: PNG or JPEG, 16:9 or 9:16, each side between 320px and
3840px, and the longest side no more than twice the shortest.

Take them in **dark theme**, which is what the app opens in and what these
assets are drawn for.
